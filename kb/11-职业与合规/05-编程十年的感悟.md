# 编程十年：十条比语言更耐用的经验

> 结论：作者写了三十万行代码、换过五门生产语言之后，把「能长期生效的东西」归成十条——**技术栈会换，判断力、表达、身体和身边的人不会**。开头那句是全篇的底色：大多数人对短期收益要求太高，对长期收益要求太低。

## 一、持续学习，但别把自己定义成「某语言的程序员」

作者的语言轨迹本身就是答案：大学 Java（Servlets → SSH：Struts2 + Spring + Hibernate），实习时发现组里用的是 Ibatis，后来换 MyBatis，框架从 Spring 换成自研 Sofa、Sofaboot；到微信支付写 C++，用内部 svrkit；做数据治理时是 Spark + Python + Hive SQL；到 AWS S3 又因为性能要求写 Rust，最后兜兜转转回到 Java。

框架也一样在换：Struts2 被 SpringMVC 取代，重框架又被 SpringBoot 替代，大厂各自有自研版本。

他的态度是：**语言只是工具**，遇到新场景自然会学；不把自己叫「Java 程序员」，只叫 Software Development Engineer。反过来，计算机世界几个月一个新框架、几年一门新语言，**只有持续学习才保得住竞争力**。

## 二、英语是回报最高的一笔投资

两条理由，都很实在：

- 最前沿的技术资料是英文，不同国家的开发者交流也默认用英语；英语好，既跟得上技术潮流，也能进社区、建立影响力。
- 远程办公普及后，英语过硬意味着**可以不住一线城市**：在老家工作、陪父母、赚外汇。

作者自己是从「及格线 90 分」开始的：大一晨读、上网找人用英语聊天、读英文文档、在 Stack Overflow 和 GitHub 用英文回答问题、把电脑和手机系统语言都换成英文。

关键的那句是：**从「学英语」变成「用英语」**。他形容英语是夜里走路的手电筒——不改变你走哪条路，但让你能扫一眼旁边那条路，需要时及时转向。

## 三、独立思考：相信，但要核实

微信年会的礼物是一块铝片，上面刻着「2022 保持独立思考」。作者借此把这条列进十年经验：

- 上级、老师、学术机构、媒体、声音大的，都不一定对；**有理不在声高**。
- 微服务很流行，不等于你这个团队、这个阶段就该上微服务；先单体跑起来、业务起来再迁，是更常见的正解。
- 技术选型时能搜到一打「看似」符合要求的组件，网上评价众说纷纭——只能自己逐项分析优劣，再结合团队特点拍板。

他没写长篇论证，只引了《切尔诺贝利》里克格勃那句 **Trust, but verify**：独立思考的第一步是**开始质疑**。

## 四、先跑起来再说

完美主义者（尤其读过《重构》和《设计模式》的）容易把时间耗在优化和重构上。作者的判断很直接：先把 MVP 上线，让用户用起来。

- 没有用户使用，再漂亮的代码也没有意义。
- 常见的问题是「做副业该用什么语言」：先做个原型、先找到第一个用户；等运行速度真成为瓶颈，业务已经大到有钱招一打人重写了。
- 代码质量的三个台阶，顺序不能倒：**make it run, make it fast, make it beautiful**。
- 他做副业最深的体会是：**技术可能是商业里最不重要的**。用户只关心好不好用、能不能解决问题，不关心你用什么语言写、代码优不优雅。

## 五、顺手的才是最好的

「什么语言最好、什么框架最好、什么编辑器最好」——这个问题没有通用答案，但社区里常为此吵起来。

他借《社会性动物》里的团队认同现象解释这种争吵：人会把自己认同的球队（或工具）当成自我的一部分，于是批评工具就像批评自己。

他的回答是：**你顺手熟悉的工具就是最好的**。编程的目的是解决问题，解决问题的工具就是你最熟的那个；除非它确实不适用，才换，别削足适履。为了乐趣学新语言另说——2017 年他学 Rust，只是因为大四没课、Rust 才发布两年，纯属好玩。

## 六、多与人交流

初入职场时他也相信「把技术搞好就行、不用管人情世故」，被朋友形容为「孤傲」。后来才认清：国内外都一样，这就是 **network and connection**。

- 技术再硬，也要被人看见；和同事、领导关系好，做出成绩时才有人抬轿子。
- 现在的做法是有事没事和同事聊天：提升熟悉度、了解部门动态、还能从抱怨里找到可优化的点。
- 他的信条：**Work hard and be nice to people**。
- 结论一句：软件工程说到底，是**人的系统工程**。

## 七、代码不是万能的

写久了会产生幻觉，觉得什么都能用代码解决——手里拿着锤子，看什么都像钉子。作者提醒要避免这种路径依赖，并且补了另一半：

**酒香也怕巷子深**。会写代码只是一半，还要写文章、在公司内部做分享、让别人「看到你」。专业能力是硬实力，营销自己是软实力，两手都要硬。他的说法是，经常跟老板聊聊天、露个脸，可能比肝十个项目还有用。

## 八、与优秀的人共事

在蚂蚁、微信支付、AWS 都待过之后，这条排进了他的前列：

- 能从优秀的人身上学到最佳实践和工程经验，Code Review 里学到更好的写法，遇到问题有靠谱的人兜底。
- 更隐蔽的收益是**技术品味**：用过简单好用的系统，就再也看不上粗制滥造、靠老板背书强推的东西；品味反过来提升设计能力。
- 附带高质量人脉，换赛道时多个选择。
- 现实一点说，大公司优秀程序员的比例更高（薪资有竞争力、招聘门槛高，微信还有面试委员会把关），所以他建议应届生有机会先去大公司见识。

## 九、身体是一切的本钱

这一条最朴素，也最不像「技术感悟」：鼠标手（腱鞘炎）、腰椎间盘突出、久坐下半身发麻、头发日渐凋零。

他的应对是工作日去公司健身房，两天有氧慢跑、两天无氧器械，坚持近三年，同时少油少糖不喝酒。原话：健身不治病，但人有精神了，扛得住高强度工作。**身体垮了，就没有后面的故事了。**

## 十、总结：马太效应

学得越多、懂得越多，再学新东西就越快——技能积累是**马太效应**。

所以程序员的竞争力不是写代码本身，也不是哪门语言或框架，而是**用技术解决问题的能力**。抓住这一条，就不必再纠结具体技术栈。
