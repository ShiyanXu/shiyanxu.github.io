# 用户分层：To B / To C，以及「傻子」争议

> 来源 #14、#18、#19、#53。产品定位不是品味问题，是**用户假设**问题。

## To B 与 To C 的根本差别

| | AI 编程工具（To B） | 手机 AI（To C） |
|---|---|---|
| 用户假设 | 用户比你更懂业务 | 用户完全不懂业务 |
| 需要什么 | Harness 工程、可控性、可集成 | 开箱即用、零学习成本 |
| 失败代价 | 工作流断裂 | 用户直接放弃 |

**只有 To B 才需要 Harness 工程。** C 端产品照搬 Claude Code 的 Harness，等于「在内部管理没有方法论的情况下做一个 Harness 产品」。

Claude Code 的 Harness 之所以好用，根源在开源社区与 Unix 哲学（小工具、可组合、可脚本化），不是靠堆功能。

## 一场真实争议（#19）

争议源起一条评论：

> 「workbuddy：给傻子用的，提供的专家你连提示词都不知道，你也真敢用……claude code：给工程师用的，命令行、目录、文件搞定一切……codex：给工程师中的懒人用的……」

博主回应：

> 「使用提示词不明的专家，期待获得良好结果的人……就是傻子。这不是歧视，这是 IT、AI 和模型的基本原理。而你们不知道找腾讯要求基本的知情权，来骂揭黑这个问题的人……就是傻子中的傻子……**本身是不同的用户群，非要用傻子这种歧视性的词。真是恶心**。」

关键立场：**不同产品面向不同用户群**，用「傻子」这类词是歧视，而不是产品分析。

## 争议背后的真问题：易用 vs 透明

「提供的专家你连提示词都不知道」揭示了一个真实矛盾：**面向大众的 AI 产品，其「专家 / 模板」往往对用户是黑箱**。

- 一方面这是易用性的代价（用户不需要理解提示词）；
- 另一方面，用户对「提示词 / 系统指令」的**知情权**诉求在上升。

这是 AI 产品在「易用」与「透明」之间的经典权衡。

## 用户的真实反馈（#53）

- 「我觉得 workbuddy 就很好用了，是我水平太低了吗」；
- 「很多人连 workbuddy 都用不好，能开始用且用好已经很好了」；
- 「没什么问题，企鹅力推的产品，肯定是对很多人来说够用且易用的」。

启示：**评价产品要放回它的目标用户**，否则所有比较都是错位的。

## 一张定位图

```
用户专业度 高 ←──────────────→ 低
            Claude Code / Codex      WorkBuddy / 通用助手
            可编程、可审计           开箱即用、模板化
```
