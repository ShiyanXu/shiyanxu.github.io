# 根基崩溃论：AI 加剧的「黑箱化」

> 素材来源：Manda Putra《学好基本功，AI 才能真正助你一臂之力》（#12 转载，宝玉xp）。这是全批内容里最有争议、也最常被转发的一篇。

## 文章的核心叙事

**AI 让 CRUD、数据解析等繁琐任务极大解放**，「只要下达指令，它就替你搞定，极大地解放了生产力」。但软件开发远不止于此——还需要**整合系统、性能优化、技术研究**，这些都需要**真正的理解力**。

## 那个咖啡馆场景

作者看到一位同行用 AI 写代码，却为了一个**极基础的问题**（一个 CSS 元素居中、`onClick` 事件里的低级 Bug）反复与 AI「拉锯」。他的内心独白是：

> 「简直可笑，花几分钟 Google 一下 CSS 的 flexbox 布局，不比你这样反复试错问 AI 快得多吗？」

更让他不安的是：这位同行理直气壮地说「还没居中呢」。

## Jonathan Blow 的警告

由此联想到 Jonathan Blow 长期警告的观点：**我们行业的知识体系，正在从根基处「崩溃」**。

布洛的忧虑是：现代软件建立在**层层叠叠的抽象之上**，如今的开发者（尤其新人）越来越依赖框架和工具（现在又加上了 AI），却**对底层原理一窍不通**——他们知道「怎样让东西跑起来」，却**不知道为什么「能跑起来」**。

当整个行业都建立在「知其然，不知其所以然」的基础上时，系统会变得异常脆弱。今天只是一个 CSS 问题，但如果未来遇到的是底层性能瓶颈或安全漏洞呢？**当没有人再理解事物的本质时，我们又该如何修复和创造那些复杂而脆弱的东西？**

## AI 加剧的撕裂

| 对象 | AI 的角色 |
|---|---|
| 经验丰富的开发者 | **杠杆**：从重复劳动中解放，专注更复杂的架构和创造 |
| 新手 | **黑箱 / 许愿机**：跳过最关键的学习和试错过程，沦为只会写 prompt 的「提示工程师」 |

结论：「一个多么吊诡的世界。一方面技术在飞速进步，另一方面，从业者的平均基本功却在退化。……真正的成长，源于**求知本身**。」

## 为什么这个论点成立（技术层面）

LLM 擅长「模式复现」而非「因果推理」。当问题落在训练分布内，AI 表现优异；一旦需要**真正的调试（debugging）**——在信息不足时定位根因——底层理解仍不可替代。

这与「模型只输出 token，执行与纠错要靠 Harness 和人」是同一结论的两种说法。

## 经济学的解释：技能偏向型技术进步

新技术提升高技能者的边际产出，同时替代或削弱低技能者的岗位价值。AI 目前呈现**两极放大**：对资深者是杠杆，对新手是「跳过台阶的电梯」，可能导致**中间层空心化**。

## 反方观点（应当一起看）

- 历史上每次抽象层上移（汇编 → C → 框架 → 云）都伴随「根基崩溃」的担忧，但软件规模依然增长；
- 「理解底层」的定义在变：今天更需要理解「系统行为与失效模式」，而不是手写指令；
- 与其要求人人懂晶体管，不如要求**每个人知道自己依赖的那一层**。

## 一条务实的结论

不必反对用 AI 跳过重复劳动，但要守住一条线：**凡是你要对结果负责的地方，你必须能判断它对不对。** 判断力不能外包。
