# 长任务与 Ralph Loop

> 一句话：**不让长上下文背锅，让每一轮都从干净的上下文重新开始。** 来源 #3、#22。

## 代表工具：CodexPotter

它不是插件，而是**独立 CLI**：后台启动 codex cli，把目标写进 `MAIN.md`，然后**每一轮都用全新、干净的上下文**，对照 `MAIN.md` 检查代码、修正、再检查，直到结果与文档一致。默认最多 6 轮（可配置）。

## 机制：为什么「每轮重来」反而更好

1. **避开 context rot（长上下文劣化）**：上下文越长，早期指令的权重越被稀释，模型容易忘目标、记错约束。
2. **目标成为唯一真相**：每轮只看 `MAIN.md` 与当前代码，判断标准不随对话漂移。
3. **失败可重试**：单轮失败不污染全局，下一轮仍是干净起点。
4. **可审计**：每一轮的 diff 与结论都能落盘。

代价：**没有中间对话记忆**。需要来回讨论、边聊边改的探索式任务不适合。

## 适用 / 不适用

| 适合 | 不适合 |
|---|---|
| 目标明确的批量任务（「按这份设计文档实现订阅系统」） | 需求还在变的探索式开发 |
| 可写成验收标准的任务 | 需要人中途做价值判断的任务 |
| 长跑、过夜、可中断的任务 | 一次性小改（开一个循环的成本更高） |

它是**任务执行器，不是聊天伙伴**。

## 与相邻概念的区别

| 概念 | 触发方式 | 上下文 | 结束条件 |
|---|---|---|---|
| Ralph Loop | 外部循环反复调用 | 每轮全新 | 产出与目标一致 |
| Agent 循环（ReAct） | 单次会话内自主循环 | 持续累积 | 任务完成 |
| Loop Engineering | 定时/事件触发 | 持久化状态 | 持续负责，无终点 |

## 名字来历

「Ralph」来自《辛普森一家》里爱重复同一句话的小孩 Ralph Wiggum，即业内所称 **Ralph Wiggum pattern**：反复用同一提示喂给 Agent，直到产出符合预期。

## 自己搭一个最小版

```
goal: 把 <文档路径> 描述的功能实现完
loop:
  1. 读 MAIN.md 与现有代码
  2. 列出「文档要求 vs 当前实现」的差异
  3. 只修差异中最靠前的一条
  4. 跑测试/构建，记录结果
  5. 若差异为空 → 停止；否则进入下一轮（最多 N 轮）
```

要点：差异清单必须由**文档**生成，不能由 Agent 自由发挥；每轮只推进一条，避免大面积重写。

## 与「可持续工作流」的区别

Ralph Loop 是「把一个目标做完」；Bridgic 的 `/build` 是「把一件事长期做下去」（定时、事件、可修改）。前者是收尾，后者是运营，见 [记忆、工作区与可持续自动化](../07-工作流与循环/05-记忆、工作区与自动化.md)。
