# 文档先行、原型驱动与工程纪律

> 把「两头理论」落到实处的一套做法：**先有你能完全理解的文档，再让 AI 写代码；传统工程纪律一样不能少。** 来源 #30、#33、#35、#36、#2。

## 一、文档先行

核心是：**先有一份你自己完全理解的、非常清晰的文档，用它来约束 AI 的行为。**

做法（#30）：

1. 让 Agent 先分析原代码、画出架构图；
2. 生成**分段的详细设计文档**，每个细节用 `/grill-me` 逐条拷问；
3. 再让 Agent 照着文档**分模块**写；
4. **写完先跑单元测试、再写业务代码**。

为缓解压缩上下文带来的召回问题，可用 1M 上下文的模型（如 Kimi K3）当「威力增强版」来读全量文档。

## 二、原型驱动开发

- 第一版先用 AI 做 UI 原型（如 Claude Design），打磨好放本地，用专门的 Skill（如 Baoyu-Design）维护。
- **做新功能前先改原型，确认后再改功能**。
- 把规则写进 `Agents.md` / `claude.md`，让 Agent 默认先改原型。
- 好处：低成本验证产品与 UI 设计；原型产物是 React 代码 + 结构化 JSON，可用 `git diff` 看清版本变更。

## 三、小版本快速迭代

每次只是一个小版本、一点点功能 + bug 修复。版本代码量不多，相对好规划、好测试验收。**避免「一次让 AI 写一个季度的工作量」**——那种产出无法验证。

## 四、传统工程纪律不能少

| 项 | 在 AI 编程里的作用 |
|---|---|
| 代码规范 | 让 Agent 的产出可读、可 review，减少风格漂移 |
| **测试覆盖** | **核心**：Agent 能自验证结果；没有测试就只能靠人肉验收 |
| 日志 | 出问题时能定位到「哪一轮、哪一步」 |
| 安全 | 涉及钱的格外小心；权限最小化 |
| 性能 | 大流量压力测试，AI 写的代码常缺性能意识 |

重点是测试覆盖——**它是 Agent 自治的前提**。

## 五、权限与安全边界

- 在 Agent 中可跳过权限确认：GitHub Copilot 的 `Settings → Copilot → Coding Agent: Allow Dangerously Skip Permissions`，勾选 `Allow bypass permissions mode`，并在对话框底部 Permission 选 Bypass Approvals。
- 官方建议**仅用于无网络的沙箱**。理由：跳过确认意味着 Agent 可执行任意命令，网络 + 文件系统同时可达时，风险不可控。
- 更普适的原则：**最小权限、独立账号、数据隔离、高风险操作人工确认**。

## 六、一页流程

```
需求 → 设计文档（人完全理解）→ 原型（先改原型再改功能）
     → 分模块实现（每模块先测试）→ 小版本验收 → 下一轮
贯穿：规范 / 测试 / 日志 / 安全 / 性能 / 权限
```
