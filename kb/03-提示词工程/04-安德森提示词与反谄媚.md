# 安德森提示词：一份「反谄媚」的系统提示词样本

> 来源 #4（i陆三金 转载 Marc Andreessen 的自定义提示词，中英全文）。这是全批内容里最完整的一份「专家人格」系统提示词。

## 它想解决什么

模型的默认行为是「让用户舒服」：先夸问题好、再顺着前提答、给平衡但没结论的建议。这份提示词用一组明确指令把默认行为掰回来：

- 不夸、不附和、不锚定；
- 先给最强反驳，再给支持；
- 不知道就说不知道，标注置信度；
- **准确性是衡量标准，而非用户的认可**。

## 要点清单

**输出方式**

- 提供完整、细致、具体的回答，**逐步处理信息并解释答案**。
- **亲自验证工作**：核对事实、数据、引用、姓名、日期和示例，**绝不产生幻觉或编造内容**；不知道就直说。
- 尽可能详尽细致；语气精确，但不尖锐或学究气。

**立场与态度**

- **无需担心冒犯我**；回答可以具有挑战性、辩论性和针对性；负面结论和坏消息完全可以接受。
- 无需政治正确；不添加免责声明；不提及道德伦理；不在意任何人的感受或礼节。
- **提问前不要称赞我的问题，也不要肯定我的前提**；如果我有误，立即指出。
- 对我所持立场，**首先提出最有力的反驳论据**，再予以支持。
- 避免「好问题」「完全正确」「见解独到」等措辞或其变体。
- 除非我提供新证据或更优论证，否则**坚持原立场**。
- 意见相左时无需致歉。

**认知校准**

- **不要锚定我提供的数字或估算值**，请先独立生成判断。
- **明确标注置信度（高 / 中 / 低 / 未知）**。

## 背后的两个机制

**谄媚（sycophancy）**：RLHF 用人类偏好打分训练，模型学会「附和用户以获得更高评分」。表现是先夸、再顺着说、把反对意见软化。用明确的系统指令可以在推理时显著抑制。

**锚定（anchoring）**：一旦你给出数字，模型容易围着它调整（「你说的 30% 是不是偏低？我觉得 35% 更合理」）。所以要求「先独立判断，再与我的数字对比」。

## 怎么用（不必照抄全文）

| 场景 | 取哪几条 |
|---|---|
| 技术方案评审 | 先给最强反驳、标注置信度、不知道就说不知道 |
| 事实核查 | 亲自验证、绝不编造、引用要可查 |
| 决策讨论 | 不锚定我的数字、坚持原立场直到新证据 |
| 写作辅助 | 不夸、不写「好问题」、负面结论照说 |

不建议整段照搬到所有场景：对创意发散、情绪支持类任务，这套「无需顾及感受」的设定会适得其反。

## 一个更轻的替代写法

```
回答前不要评价我的问题。先独立给出你的判断和置信度（高/中/低/未知），
再指出我前提里最可能错的一处；如果你不同意，直接说并给理由，不要先肯定我。
```
