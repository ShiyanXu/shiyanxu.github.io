# Step back：Agent 原地打转时的急救词

> 来源 #56。一个真实调试片段，价值在于「纠偏时同时冻结目标」。

## 用法

当 Agent 没有实质性进展、在原地打转时，喊一句 **「Step back」**：让它暂停当前路径，重新看目标是什么、当前路径是否有问题。

作者另一个常用词：「**跳出既定框架**」。

## 真实片段（让 Agent 调试音色克隆）

用户发出：

> 「我建议你先暂停一下，重新看一下文档，是不是有参数或者用法没有注意到，**step back 重新思考当前路径是否正确，目标不变：在保证音色的前提下中文地道**」

Agent 的响应：

1. 停止生成试验；
2. 重新核对官方文档 / 示例 / 推理代码；
3. 检查当前接入是否有偏差（参考音频的作用、任务提示格式、Base/Flash 的采样参数、是否有遗漏的音色控制方式）；
4. **明确保持目标不变**；
5. 指出「后几轮偏离了可靠用法：无参考音频的声音描述是在生成新音色，而随意追加语言要求超出了官方标准提示模板」；
6. **回滚了未提交的代码**。

## 要点：纠偏时同时「冻结目标」

只喊「step back」有风险：Agent 重规划时可能顺手把目标也改了（从「保住音色」滑向「先让它能跑」）。

所以句式是：

```
step back，重新思考当前路径是否正确。目标不变：<写死不变的目标>。
```

目标一旦写死，Agent 只能改「路径」，不能改「靶子」。

## 三个触发信号

- 连续 2–3 轮改动没有让测试通过；
- 开始修改与问题无关的文件；
- 开始「绕开」报错（注释掉、加 try/catch、跳过用例）。

出现任一信号，立即 step back，而不是继续喂更多提示。

## 为什么有效：退一步提示（Step back prompting）

源自 Google 2023 年论文 *Take a Step Back: Evoking Reasoning via Abstraction in Large Language Models*：先让模型**抽象出高层原理 / 概念**，再基于抽象去推理具体问题。

与这里的用法（重看目标、检查路径）精神一致——都属于「先跳出局部、回到全局」的元认知干预。

## 组合用法

| 场景 | 组合 |
|---|---|
| 调试跑偏 | step back + 冻结目标 + 要求列出「已验证 / 未验证」假设 |
| 设计跑偏 | step back + 重述需求 + 要求给 2 个替代方案 |
| 反复改同一处 | step back + 要求读原始文档/规范，而不是读自己上一轮的输出 |
