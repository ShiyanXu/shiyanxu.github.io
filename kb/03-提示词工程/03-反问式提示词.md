# 反问式提示词：先提问，再回答

> 来源 #72、#73。一句话加在问题后面，把「需求澄清」从人转移给模型。

## 模板

在告诉 AI 问题之后，加上：

> 「请你在正式回答之前，先向我提问，每次只提出一个问题，并根据我的回答继续追问。直到你有 95% 的把握，能够充分理解我的真实需求与最终目标时，再给出完整方案。」

## 为什么有效

- **补齐缺失背景**：多数「答非所问」不是模型笨，而是需求里缺关键约束。
- **强制单问题**：一次只问一个，避免用户面对 10 个问题直接放弃。
- **明确停止条件**：「95% 把握」给了模型一个可判断的收敛点，不会无限追问。

这本质是把**需求澄清（requirement elicitation）**从人转移给模型。

## 适用与不适用

| 适合 | 不适合 |
|---|---|
| 需求模糊的产品/架构讨论 | 已经写清楚的一次性小任务 |
| 要产出方案、文档、计划 | 事实查询（「这个 API 怎么用」） |
| 跨部门、跨角色沟通 | 时间极紧、必须立刻给结果 |

对简单任务用它，只会多花几轮对话。

## 社区已把它固化成 Skill

评论区指出，已有人把「先反问再回答」封装成 skill 并开源：`/grill-with-docs`（带着文档拷问）、`/grill-me`（拷问我）。社区作者把自己开发的经验都开源了，比视频里的提示词更好用。

启示：**好提示词 → 固化成 Skill** 已是主流路径。

## 变体

**A. 带文档版**：先让模型读文档，再提问——「读完后先问我三个问题，确认我理解的和文档一致」。

**B. 带选项版**：「每次提问给我 2–3 个选项，而不是开放式问题」——降低回答成本。

**C. 反向版（用于评审）**：「先复述你理解的需求，列出你不确定的地方，再开始」。

## 注意

- 反问会**消耗轮次**，长任务里要有心理预期；
- 如果模型问的问题质量差，先给一句「问题要能改变方案，不要问无关细节」。
