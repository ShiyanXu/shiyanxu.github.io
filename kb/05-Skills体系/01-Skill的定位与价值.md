# Skill 的定位：模型越强，为什么反而更需要 Skill

> 来源 #27（魔法师蛋小丁）、#57（OpenAI 文章）、#15。这个问题的答案决定了整个 Skills 生态的合理性。

## 被质疑的问题

当 GPT-5.6 Sol、Kimi K3、Fable 5 这类模型已经很强时，「纯系统提示词类的 Skill」还有必要存在吗？

## 回答：读书与积累的价值

一本书可能不足 1M token，但阅读时**每个段落都在学习与思考**，积累的上下文远不止 1M。所以「让模型读一本书」并不能生成很好的 Skill——**Skill 不是文本搬运，是判断力的固化**。

结论：**通过学习和阅读提升自己的品味和判断力仍然有价值**。Skill 本质是「人把品味与流程固化下来」的载体，模型再强也替代不了这一层。

## Skill 真正解决的问题

| 问题 | Skill 的解法 |
|---|---|
| 每次对话重复贴同样指令，费 token 且不稳定 | 一次打包，相关时自动激活 |
| 流程只存在某个人脑子里 | 落成目录，可版本化、可评测、可发布 |
| 模型不知道「你们团队的规矩」 | 把规矩写成指令，按需加载 |
| 好提示词用完就丢 | 固化成 Skill，全团队复用 |

一句话：**Skill 是一种软件资产，不是一段提示词。**

## 官方也在重思 Skill（#57）

OpenAI 文章《Rethinking skills and prompts for GPT-6 Astra》篇幅不长但含金量高。一个实用技巧：**把其中「Better skills」章节直接复制给模型，让模型审查并优化你自己的 Skill。**

## 一个反面参照

「去 AI 味」这类 Skill 的存在说明：市场已经细分到**写作风格治理**层面。AI 生成的文本需要「去味」，本身就是 AI 时代的新需求——**Skill 生态的边界，等于人类经验可被固化的边界。**

## 判断一个 Skill 值不值得写

- 这件事**会重复发生**吗？（一次性任务不值得）
- 这件事**有明确的好坏标准**吗？（没有标准就无法评测）
- 这件事**模型默认做不好**吗？（模型已经做得很好就不必写）
- 这件事**需要外部知识/工具**吗？（需要则配合 MCP）

四条都「是」，才值得写。
