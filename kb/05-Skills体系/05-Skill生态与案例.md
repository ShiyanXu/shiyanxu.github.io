# Skill 生态与典型案例

> 一份「别人已经做出来的 Skill」的样本集：看它们解决什么问题、怎么触发、有什么可借鉴的设计。来源 #11、#15、#16、#24、#26、#32、#37、#43、#61、#73。

## 一、资源站：skills.qiaomu.ai

作者乔木，理念是**只放少而精**：共收录 **333 个 Skill**，每个分类下不超过 10 个。

覆盖方向：内容生产、UI 设计、上传模板、数据质量与自动化运维、安全审计与发布合规、创业产品与内容体系、AI 应用出海、AIGC 素材生成、认证与实战、Agent CLI 原理与规范、GitHub 与开源维护、出海增长、垂直行业。

**可借鉴的产品决策**：用「每类不超过 10 个」倒逼质量，而不是比谁收录多。这与 Skill 的加载机制（描述词越多越容易抢触发）一致。

## 二、设计类：OJO Design Skills（#43）

即插即用的设计类 Skill 包，让 AI 编程代理「学会做真正的设计决策」，而不是生成千篇一律的「AI 味」界面。

包含：品牌驱动的视觉方向、设计令牌（design tokens）、组件配方、动效规范，以及一套严格的**反模式护栏**。

对做前端/PPT 的人，这类 Skill 的价值是**把「审美」变成可执行的约束**。

## 三、对抗模型惯性：geju（让 Codex 格局打开，#11）

对抗 Codex「过度谨慎 / 求稳」的四大问题：

1. 常因害怕破坏东西，而保留旧行为、旧命名、旧路径、别名、shim 和双轨流程；
2. 常在看整体系统前，就钻进某个字 / 函数 / 段落或迁移路径；
3. 常给出礼貌、平衡、低风险但**不解决问题**的答案。

安装后用关键词「格局打开」激活，内置**终局倒推 / 零历史包袱假设 / 反向约束**等方法论。

启示：Skill 不只用来「加能力」，也可以用来**改模型的默认倾向**。

## 四、写作风格治理：less-ai-tone（去 AI 味，#61）

GitHub 项目 `larashero3-dotcom/liefiat-less-ai-tone`，用语言学研究方法**量化「什么是 AI 味」**。

- 语料：629 篇文章（282.6 万汉字、9.5 万句、4.6 万段）。其中 300 篇由 5 个主流模型在受控条件下生成，329 篇为人类写作。
- 方法：检验 26 项「公众认为有 AI 文风」的候选特征。
- 结果：**11 项通过检验**，有显著区分度。

关键数据：

| 特征 | 人类 vs 生成 |
|---|---|
| 设问句用词 | 区分力最强，**4.4 倍** |
| 比喻 | 人类是生成文本的 **2.4 倍** |
| 正文设问句 | 人类是生成文本的 **17 倍** |
| 句内同构排比 | 人类高于生成文本 |

不同模型的「AI 味」也不同（每千字）：

| 模型 | 破折号 | 提示性冒号 | 问句小标题 |
|---|---|---|---|
| DeepSeek | 5.16 次 | 最重之一 | — |
| Claude | 4.25 次 | 最重之一 | — |
| GPT | 0.11 次 | — | — |
| Gemini | — | — | 最重 |

**这是全批内容里最硬的一块数据**：它把「文风」从审美问题变成了可统计、可检测、可回归的问题。

## 五、内容生产：info-digest（#15）

把 AI 资讯整理成可发布内容，四条原则：读者视角、联网核查、交代背景、适配平台格式（X/微博偏纯文本、短小精炼）。完整 SKILL.md 示例见 [Skill的结构与渐进式披露](02-Skill的结构与加载.md)。

## 六、配图与交付：baoyu-design（#16）

制作 PPT / 动画 / 网站时，可调用 AI 生图 Skill 配图（Codex 用内置画图工具；Claude Code 配合 baoyu-image-gen 调用 Codex CLI），自动在 PPT 合适位置插入配图，**连图导出为 PPTX**，再用 PowerPoint / Keynote 二次编辑。

启示：Skill 的终点可以是**一份能交付的文件**，不只是文本。

## 七、模拟推演：热搜推演 + MiroFish（#24）

```
抓取当前热搜 → 先问你想衍生创作哪条 → 自行检索整理事件
→ 塞进 MiroFish，用数百个 Agent 模拟真实社交网络
（扮演当事人、消防、被困群众、媒体等）互相推演事态
→ 生成 72 小时推演报告 + 若干条社交文案
```

这是「Skill 编排多 Agent 模拟」的代表：Skill 负责流程，MiroFish 负责仿真。

## 八、跨模型协作：Kimi Code + ChatGPT（#26）

一个让 Kimi Code **一边写代码、一边与 ChatGPT 讨论**、做研究、设计架构的 Skill。用外部模型补自己的盲区，是「多模型分工」的轻量版。

## 九、提示词固化的证据：grill-me / grill-with-docs（#73）

提示词视频的评论区指出，已有人把「先反问再回答」封装成 skill 并开源：`/grill-with-docs`、`/grill-me`。这印证了**「好提示词 → 固化成 Skill」已是主流路径**。

## 十、文档转换：pdf-to-obsidian

把 PDF 论文 / 教材 / 讲义转成可批注、可链接的 Obsidian 笔记。

**处理流程**（这就是它的全部价值）：

```
解析：标题、作者、日期等元信息；章节编号 → Markdown 层级；保留粗体/列表/表格
公式：$...$ 与 $$...$$ 原样保留为 LaTeX（Obsidian 配 MathJax）
图片：无法提取时留 ![描述](占位符)，并提示人工补充
结构化：开头写 YAML frontmatter（title / author / year / source / tags / created）
```

**为什么它是个好样本**：输入输出极明确（一份 PDF → 一份 md），因此**可以验收**；失败也能降级（用户直接粘贴文本）。

**可迁移的一条原则**：文档转换类 Skill 的价值不在「聪明」，而在**输出契约固定**——每次产出的结构、字段、命名都一样，人才敢批量用。

## 十一、从这些案例里提炼的共同点

1. **触发词很具体**：不是「帮你写作」，而是「当你要发布社交文案时」。
2. **只解决一类问题**：设计就是设计，写作就是写作，不贪多。
3. **把隐性标准显性化**：反模式护栏、11 项文风特征、四条写作原则。
4. **可交付**：输出 PPTX、报告、发布稿，而不只是「建议」。
