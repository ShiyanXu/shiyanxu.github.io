# 实战：用 DSH 给项目生成一份 README

> 一个六步小任务，把「工作区 → 目标 → 指令 → 观察 → 审阅 → 收尾」的主线全走一遍。

## 任务

> 分析当前工作区的项目，生成一份 README.md，包含项目简介、主要功能和使用说明。

## 六步

**1. 确认环境**（三样缺一不可）
- DSH 已启动，浏览器能打开界面；
- 顶部状态区显示可用模型；
- 侧边栏已有项目工作区，输入框可用。

**2. 新建会话，先设目标**

> 设定目标：为当前工作区的项目生成 README.md，只做这一件事。

**3. 发任务指令**

> 分析这个项目是做什么的，然后生成一份 README.md，包含项目简介、主要功能和使用说明。先读一下项目的关键文件再动笔。

指令里要含三件事：**做什么**（生成 README）、**产出在哪**（README.md）、**怎么干**（先读关键文件）。指令越具体，结果越可控。

**4. 观察它干活**

盯住消息流的工具调用树：
- Shell：列目录、看文件；
- Glob：找 README、`package.json`、源码入口；
- Read：读关键文件；
- Think：组织结构。

反复「读一下、想一下、再读一下」是正常的——它在建立理解，不是在卡住。

**5. 审阅结果**

两件事：打开生成的 `README.md` 检查三部分是否到位；不满意直接说「把使用说明写详细点，加一个安装步骤」。

**6. 收尾**

总结过程、切轨迹视图复盘、归档会话，再开下一个。

## 这次任务用到了什么

| 环节 | 能力 |
|---|---|
| 环境确认 | 启动、模型、工作区 |
| 防跑偏 | 目标 |
| 指挥干活 | 会话与指令 |
| 观察过程 | 工具调用树 |
| 安全边界 | 权限模式 |
| 收尾管理 | 归档、轨迹视图 |

## 可以接着练的三个方向

- **计划模式**跑大改造：重构前先让它出方案；
- **子代理**并行调研：多方向同时查；
- **后台任务**跑长活：构建、批量处理不堵对话。
