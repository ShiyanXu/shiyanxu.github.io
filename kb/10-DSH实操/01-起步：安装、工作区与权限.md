# DSH 起步：安装、工作区与权限

> DSH（DeepSeek Harness）是一个本地运行的 Agent 工作台：终端起服务，浏览器操作。本篇只讲「怎么把它跑起来、怎么划定它的地盘」。

## 安装与启动

```
npx @deepseek-ai/dsh web          # 启动图形界面
npx @deepseek-ai/dsh web --port 8080
```

- 需要 **Node.js 22 及以上**；
- 以**终端打印的地址**为准，浏览器打不开时先核对端口。

## 工作区：给 Agent 一个地盘

- 添加的是**文件夹**，不是单个文件；同一目录只能添加一次；
- 删除工作区只是移除分组记录，**文件与会话都保留**；
- 一个工作区对应一套可访问的目录边界，也是权限模式的生效范围。

## 权限模式：它能不能动你的文件

| 模式 | 能力 | 适合 |
|---|---|---|
| **Read Only** | 只能读，不能写、不能执行有副作用的命令 | 审阅、调研、只读分析 |
| **Workspace Write** | 能在工作区内写文件、跑命令 | 日常开发（默认） |
| 审批 | 越界操作弹确认，逐条放行或拒绝 | 想更严时的兜底 |

判断原则：**看到审批弹窗，说明它想动工作区以外的东西**——先看清操作内容再决定，不要无脑放行。

## 常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `npx` 下载慢/失败 | 网络与镜像 | `npm config set registry https://registry.npmmirror.com` |
| 端口被占用 | 已有服务 | `--port 8080` 换端口 |
| `node -v` 版本太老 | Node < 22 | 装最新 LTS |
| 界面打不开 | 地址/端口不一致 | 以终端打印为准，确认无报错再刷新 |
| 侧边栏没有新工作区 | 选成了文件或重复目录 | 选文件夹，同一目录只加一次 |

## 跑偏了怎么办

| 症状 | 先做什么 |
|---|---|
| 方向跑偏 | 一开始就设目标；跑偏时直接说「停，回到目标上」 |
| 长时间不结束 | 看工具调用树卡在哪；长任务丢后台；指令里限定范围 |
| 结果不满意 | 先换更强模型或调高推理等级，再检查指令是否足够具体 |
| 频繁弹审批 | 它在碰工作区外的东西，按需放行或收紧权限 |

一句话：**指令含糊，结果必然含糊。** 换模型只能补救，不能替代说清楚。
