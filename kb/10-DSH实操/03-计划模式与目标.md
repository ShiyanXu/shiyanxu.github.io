# 计划模式与目标：两个防跑偏的开关

> 结论：**计划模式管「先看方案再动手」，目标管「每轮对照靶子」。** 一个前置，一个全程。

## 计划模式（`/plan`）

进入 / 退出：

```
/plan                      # 进入计划模式
/plan 帮我重构登录模块的权限校验   # 带任务进入
/plan off                  # 退出
```

进入后，Agent 的行为变成四步：

1. **先研究**：读代码、理清现状，只读不动；
2. **出计划**：把步骤整理成一份计划给你看；
3. **等你审阅**：批准或提修改意见；
4. **按计划执行**：每一步对应计划里的一项。

界面上会显示计划模式状态（等待审阅 / 执行中），你能看到它「打算干什么、干到哪」。

**适用**：改动大（重构整个模块）、牵扯面广（一处改影响十几个文件）、不容出错（数据库迁移）。

**不是万能药**：它是**软约束**，只引导「先计划后执行」，不限制工具权限——权限边界仍由权限模式管。日常小任务开了反而多一道审阅。

## 目标（Goal）

**为什么需要**：不设目标，Agent 修完 bug 会顺手优化布局、整理代码风格，最后偏离主线。

**怎么设**：不需要按钮，直接在对话里说。

```
本次会话的目标是：修复登录页在手机端显示错乱的问题。现在开始排查。
设定目标：先把登录页 bug 修完，其他优化都先不做。
```

设完界面上会出现目标状态，Agent 每轮决策都对照它。

### 目标的四个状态

| 状态 | 含义 |
|---|---|
| 进行中 | 正在朝目标推进 |
| 已暂停 | 暂时搁置，可能被别的事打断 |
| **受阻** | 卡住了，需要你介入（缺权限、缺信息） |
| 已完成 | 目标达成 |

「受阻」是它主动求助的机制：干不动就说，而不是硬编。

### 目标要写得收敛

「把 README 补全」比「把这个项目完善一下」管用得多。**目标模糊，Agent 就没法判断什么算跑偏。**

判断标准：目标能不能用一句话回答「做完了没」。

## 两个开关怎么配合

```
大改动：/plan 出方案 → 批准 → 设定目标 → 执行
小改动：设一个收敛的目标 → 直接干
长任务：目标 + 后台任务（见下一篇）
```
