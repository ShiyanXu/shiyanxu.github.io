# 子代理、后台任务与工作流：三种「把活分出去」

> 三者的分工：**子代理解决「拆开并行」，后台任务解决「不用等」，工作流解决「按固定套路跑」。**

## 子代理（Subagent）

**是什么**：主 Agent 把任务拆开，委派给拥有独立上下文的子 Agent 并行执行，最后收集结果汇总。

**怎么触发**：不需要按钮，直接说。

> 用两个子代理并行调研：一个查这个框架的文档，一个查社区的实践案例，最后汇总

Agent 判断任务适合拆分时也会自己派。

**界面上能看到什么**：
- **子代理行**：消息流里每个子代理一行，显示领了什么任务；
- **完整转写**：点开是子代理自己的完整对话（思考、工具、交付）；
- **子代理导航**：可以从父会话进入子会话；
- **并行状态**：多个子代理各自独立显示。

**能对它做什么**：发消息补充信息、打断、查看子代理列表。

**什么时候用**：

| 场景 | 收益 |
|---|---|
| 多方向调研 | 并行查，省时间 |
| 前后端/多模块并行改 | 互不阻塞 |
| 独立子任务 | 上下文隔离，不互相干扰 |

**不适合**：任务紧密耦合、改一处影响全局——交给一个 Agent 从头做更稳。

## 后台任务

**是什么**：把耗时任务（完整测试套件、批量处理、大项目编译）放到后台，对话立刻恢复可用，跑完回来收结果。

**怎么用**：

> 把这个批量压缩任务放到后台执行，完成后告诉我结果

会话头部会出现后台任务列表，状态实时更新。

**五种状态**：运行中 / 停止中 / 已完成 / 失败 / 已终止。常见类型是命令行任务与子代理任务。

**实践建议**：
- 长任务默认丢后台；
- 后台任务太多会互相抢资源，没用的及时终止；
- **任务完成 ≠ 结果正确**，收到汇报后抽验一下。

## 工作流

**是什么**：把固定套路写成编排脚本——每一步干什么、何时启动子代理、子代理之间怎么衔接，一条命令跑完整条流水线。

**与普通任务的区别**：

| 对比 | 普通任务 | 工作流 |
|---|---|---|
| 流程 | 临时决定，边想边干 | 脚本固化，按步执行 |
| 子代理 | 现场拆 | 脚本里编排，自动启动 |
| 复用 | 每次重来 | 一套脚本反复跑 |
| 适合 | 一次性任务 | 重复性流程 |

**怎么用**：告诉 Agent「把这个流程写成工作流跑一遍」；运行过程中，界面以嵌套展开展示每一步，可以逐层看它调了哪个子代理、干了什么。

**什么时候值得**：固定流程反复跑（每周数据报告）、多步骤强依赖（第 1 步产物是第 2 步输入）、多子代理协作。

**学习曲线**：这是三者里最进阶的。先把「认识它、跑现成流程」跑通，再学自己写编排。

## 一张选择表

| 你的问题 | 用 |
|---|---|
| 活太多、方向多、可以并行 | 子代理 |
| 单步太慢、不想被堵住 | 后台任务 |
| 同一套流程要反复跑 | 工作流 |
| 三者叠加（长流程 + 并行 + 异步） | 工作流编排子代理，子代理内部再丢后台 |
