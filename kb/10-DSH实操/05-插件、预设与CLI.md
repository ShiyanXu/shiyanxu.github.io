# 插件、预设与 CLI：DSH 的三种「换形态」

> 插件决定「有哪些能力」，预设决定「Agent 长什么样」，CLI 决定「用什么方式启动」。

## 插件：能力的零件

设置 → **插件**。页面上方说明就一句：**配置和查看本部署已安装的插件**。

几个核心插件是能力地基：

| 插件 | 控制什么 |
|---|---|
| 终端 | 限制 Agent 运行的每一条命令（执行范围、是否启用沙箱） |
| Agent 循环 | Agent 如何派发工具调用 |
| 网页搜索 | 搜索提供方 |

插件列表里能看到每个插件的名称、运行状态、配置入口。

**插件 vs 技能**（最容易混的一对）：

| | 技能（Skill） | 插件（Plugin） |
|---|---|---|
| 是什么 | 给 Agent 的「说明书」 | 能力的「零件」 |
| 管什么 | 怎么完成某类任务 | 工具、界面、循环本身如何装配 |
| 在哪用 | 会话里 `/` 调用 | 设置里管理/安装 |

一句话：**技能是内容，插件是装配。**

## Agent 预设：新会话的出厂配置

设置 → **Agent 预设**。内置四个，能力从全到简：

| 预设 | 能力 | 适合 |
|---|---|---|
| **标准模式** | 文件编辑、Shell、检索、技能、计划、目标、子代理、工作流 | 日常默认（推荐） |
| **PTC 模式** | 标准能力，但工具通过 Code Mode SDK 呈现，模型用 TypeScript 组合多步操作 | 喜欢程序化控制 |
| **极简模式** | 只保留持久 bash 与文件编辑 | 极简环境、专注跑命令 |
| **创造模式** | 标准能力 + 运行时检查、插件实验、创作指导 | 制作自定义预设 |

**切换的影响**：新会话用新预设，**已存在的会话保持开始时的预设不变**。主界面顶部状态区显示当前预设。

自定义预设走「创造模式」：按创作指导调行为与插件组合，保存成自己的预设。

## CLI：图形界面之外的入口

```
dsh web                             # 图形界面，日常交互
dsh --profile headless "任务"        # 跑一次，打印结果后退出
dsh --profile <名字>                 # 指定配置档案
dsh plugin --profile <名字> <参数>    # 管理该档案的插件
```

**headless** 适合自动化、脚本、CI：一条命令把任务干完就退出，结果直接打到终端。

```
export DEEPSEEK_API_KEY="你的密钥"
dsh --profile headless "总结当前目录下这个项目的结构"
```

**profile** 是一套独立的插件组合与配置：`web` 与 `headless` 内置，首次使用自动初始化；其他 profile 用 `dsh plugin` 创建，各自互不干扰。

## 三者的关系

```
插件  → 装配出能力
预设  → 选一套插件组合，决定 Agent 形态
CLI   → 用哪个 profile 启动
```
