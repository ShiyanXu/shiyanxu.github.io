# 实战：Blender 建模、MMD 自动化，以及 adb 报销闭环

> 三个案例，分别对应「MCP 替代 Computer Use」「Skill 编排 MCP」「Computer Use 补空白」。来源 #23、#50、#51、#55。

## 案例一：Blender 建模，用第三方 MCP 而不是 Computer Use

- 用 GPT-6 Astro 做 Blender 建模，走的是**第三方 MCP 插件**：把链接丢给 Codex 让它自己装即可。
- **不需要用 Computer Use，也不要用官方 MCP 插件**——网上看到的「建模」演示基本都基于这个第三方 MCP。
- 更曲面、更复杂细致的模型，需要用 **Tripo**（文本/图像生成 3D 模型的服务）。
- 参数建议：**思考强度设为 Medium，通过 `/goal` 设置目标，不要一味提高思考强度。**

评论区补充（#51）：

- 想做 MMD 也是同一个 MCP，再装 **mmd-tools** 插件即可；
- 有人问「约 5 万行规模的 Python 代码适合什么思考等级」，博主反问「看你代码是什么业务了」——**强度要按任务形态定，不能按代码量定。**

## 案例二：把「看教程」也自动化（#23）

MMD 有很多背景知识，需要「一边看视频一边教 Codex」。于是作者写了个 Skill：

```
自己去 B 站搜教程 → 下载视频 → 音视频分离 → 音频转录
→ 用 openCV 找出关键画面并识别 → 变成图文教程让 Codex 自己看
```

结果是「啥也不会的我也能做 MMD 了」。

**这是「Skill 编排 MCP，把非结构化的人类知识（视频）转成 Agent 可消费的文本」的典型**：MCP 提供下载/转录/抽帧能力，Skill 规定顺序与产物格式。

## 案例三：Computer Use 做真实业务闭环（#55）

让 Codex 用 **adb** 操作手机：

```
在携程 / 飞猪上开发票
→ 通过浏览器的 Computer Use 插件进入邮箱，把发票下载下来
→ 读取发票内容计算金额
→ 整理成报销单
```

面对**没有 API、没有 MCP 的存量系统**（出行 App、网页邮箱），这就是 Computer Use 的合理用法。

配套的隐私讨论：

- 担心「个人隐私数据暴露给 Codex」「数据密钥暴露」「账号与数据隔离」；
- 博主回应：正常使用封号概率不高，**滥用更容易封**；不要做违规或出格的事。

## 三个案例的共同结构

| 环节 | 由谁负责 |
|---|---|
| 触达系统 | MCP（首选）/ Computer Use（兜底） |
| 操作顺序与判断 | Skill |
| 执行与重试 | Harness |
| 高风险确认 | 人 |
