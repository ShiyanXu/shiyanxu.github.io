# MCP 配置与安全边界

## 通用配置格式

```json
{
  "mcpServers": {
    "blender": {
      "command": "uvx",
      "args": ["blender-mcp"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/workspace"]
    }
  }
}
```

要点：

- 大多数客户端用同一形态（`command` + `args` + 可选 `env`）；
- **路径要写绝对路径**，相对路径会随工作目录变化而失效；
- 装第三方 Server 前先看仓库维护状态、star、最近提交与 issue。

## 接入真实系统时的风险模型

把 MCP 接到本地文件、邮箱、支付/发票类服务时，等于把「账号与数据的钥匙」交给 Agent。

| 风险 | 表现 | 对策 |
|---|---|---|
| 越权访问 | Agent 读到与本任务无关的文件/邮件 | 最小权限：只挂载必要目录，只授只读 |
| 凭据泄露 | API key 被写进日志、提交进仓库 | 用环境变量注入；密钥扫描；独立账号 |
| 误操作 | 删除、发送、付款 | 人类在回路确认高风险操作；沙箱禁网 |
| 交叉污染 | 一个任务的数据进入另一个任务 | 数据隔离：按项目分 Server / 分目录 |
| 供应链 | 第三方 Server 带后门 | 固定版本、审代码、优先官方/知名维护者 |

## 为什么「跳过权限确认」只建议用于无网沙箱

跳过确认意味着 Agent 可执行任意命令。当**网络 + 文件系统同时可达**时，一条命令就可能把数据外传或把木马落地。官方因此建议 `Allow Dangerously Skip Permissions` **仅用于无网络的沙箱**（#2）。

## 一条可执行的安全清单

```
1. Server 只暴露必要工具，默认只读
2. 目录白名单，禁止挂载 home 全量
3. 密钥走环境变量，绝不写进 SKILL.md / 仓库
4. 高风险动作（付款、发信、删除）必须人工确认
5. 沙箱断网；需要联网时单独开一个受限网络
6. 定期审计 Agent 的调用日志
```
