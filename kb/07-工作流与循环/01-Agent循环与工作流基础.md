# Agent 循环与工作流基础

> 先把「Chat 和 Agent 到底差在哪」说清，后面所有工作流概念才有落点。来源 #18、#71、#28。

## Chat / Agent / 智能体的区别

- **聊天**：用户发一句、AI 回一句，这一轮就结束。
- **智能体**：输入之后，AI 希望用工具去达成「任务完成」，**以任务的完成作为结束**——这叫 loop。

一句话：**聊天以「回复完成」为终点，Agent 以「任务完成」为终点。**

## Agentic Workflow 的骨架

```
感知（Perceive）→ 规划（Plan）→ 行动（Act，调用工具）
      ↑                                    ↓
      └────────── 观察结果（Observe）←──────┘
```

循环终止条件不是「输出了文本」，而是「任务完成」。

## 用 AI 最好的方式是「梳理工作流」（#28）

把想法一步步落地，通过工具、接口一步步落地，然后融入现在的需求——「一不小心效率值拉满了」。

内涵：**AI 的价值不在单次问答，而在把重复性流程固化成可复用的自动化链路。**

## 开发循环 v1.1（#71）

把循环拆成两层：

| 层 | 环节 | 由谁驱动 |
|---|---|---|
| **小循环** | 表达（需求澄清）→ 小试 → 确认 | GPT-6 Astro |
| **主循环** | 开发 → 验收 → 下一轮需求 / 修复 | 人 + Agent |

小循环解决「说清楚」，主循环解决「做对」。两层都转起来，才是稳定的开发节奏。

## 一次性任务 vs 可持续工作流

真正有价值的是**可长期运行、定时执行、随时修改、持续优化的工作流**，它需要三样东西：

1. **持久化状态**（记忆 / checkpoint）；
2. **触发器**（定时、事件、Webhook）；
3. **可观测与可编辑**（人能看懂、能改）。

三者缺一，就会退化成「一次性脚本」。

## 判断你的任务该用哪种形态

| 任务特征 | 形态 |
|---|---|
| 一次问答能解决 | Chat |
| 一次会话内多步工具调用 | Agent 循环 |
| 有明确目标、要跑很多轮 | Ralph Loop（见 [长任务与Ralph-Loop](../01-Agent心法/03-长任务与Ralph-Loop.md)） |
| 要长期、定时、可改 | 可持续工作流（见 [记忆、工作区与可持续自动化](05-记忆、工作区与自动化.md)） |
