# 循环的五个动作：发现、交接、验证、持久化、调度

> 结论：**一个能自己转起来的循环，缺的不是更强的模型，而是五个动作齐全。** 少一个，循环就退化成人肉操作。

## 五个动作

| # | 动作 | 一句话 | 产出 |
|---|---|---|---|
| 1 | **发现 Discovery** | 让循环自己找活干，而不是等人列清单 | 边界清晰、可用软件判定「做完没」的任务 |
| 2 | **交接 Handoff** | 给每次运行一个隔离、可丢弃的工作区 | 任务说明 + 约束 + 允许改动的文件范围 |
| 3 | **验证 Verification** | 由写代码之外的一方判分 | 确定性检查结果（编译/测试/字段/HTTP 200） |
| 4 | **持久化 Persistence** | 把记忆放在对话上下文之外 | STATE.md / issue / 数据库 + 审计物 |
| 5 | **调度 Scheduling** | 让循环在该醒的时候醒过来 | 定时/事件触发 + 每次运行的摘要 |

### 1. 发现

来源可以是：CI 失败列表、issue 队列、新 commit、收件箱、分析告警、文档漂移扫描。

**没有发现环节，循环只会反复做同一件已完成的事。**

### 2. 交接

用 git worktree / 容器 / 临时环境，**一次运行一个分支**。

隔离的意义：**让「失败一轮」变便宜**——直接丢掉，不污染主线。交付内容要写清四件事：任务、约束、上下文、可改范围。

### 3. 验证

顺序是硬的：
1. 先跑**确定性检查**：编译、测试、字段齐全、API 返回 200；
2. 规则判不了，才上小模型 referee 或人工闸门。

**铁律：生成者不给自己的作业打分。**「agent 说做完了」不构成证据。

### 4. 持久化

记录**已完成、待办、上次为什么失败**。循环会跨崩溃、重启、调度间隔运行，**状态不落盘 = 每轮从零开始**。

同时留审计物：分支名、日志、测试输出、PR 链接。

### 5. 调度

cron / launchd（Mac）/ 任务计划程序（Win）/ CI 事件 / webhook / 队列。

**调度是把「一次运行」变成「一个循环」的那一步。** 每次唤醒都要留摘要：有结果给结果，没结果给一句 no-op。

## 核心洞察：自主性上限 = 可验证范围

> 想更自主，不要去调 agent 的参数，要去**扩大它能验证的范围**。

| 区域 | 内容 | 能怎么跑 |
|---|---|---|
| 可独立验证 | 测试、构建、类型检查、CI 全绿 | 可以放心跑通宵 |
| 验证不到 | 观感、取舍、口径判定、合并、部署、付款、发信 | 必须有人 |

一个有快速可信测试套件的仓库能安稳跑一整夜；一个「对不对要靠人看 UI 感觉」的仓库，循环走不到人不在的地方。

## 九条设计要点

1. **把「完成」写成可执行断言**：❌「持续研究直到你充分理解」 ✅「五个问题各至少一个来源，且来源域名互不相同」。
2. **生成者 ≠ 评估者**：至少换上下文，最好换模型。
3. **执行要隔离**：一轮一个 worktree/容器。
4. **状态必须走出窗口**：不落盘就是每轮从零。
5. **三条正交预算**：迭代数、token、墙钟时间——谁先耗尽谁触发退出。
6. **无进展检测**：比对每轮 tool-call 签名与状态哈希，连续两轮相同就强制退出，别等撞上限。
7. **停止原因分类记录**：`done_verified` / `budget_exhausted` / `no_progress` / `max_iterations` / `human_abort`。
8. **人类闸门只放在不可逆动作之前**：merge、部署、付款、发信；其余环节别拦，否则循环等于没用。
9. **监控停止原因分布**：`max_iterations` 或 `no_progress` 占比上升，是提示词/工具设计的回归信号，**比用户抱怨更早出现**。

## 四种循环，选错类型是最常见的初级错误

| 类型 | 靠什么推进下一轮 | 靠什么停 | 适合 |
|---|---|---|---|
| **Turn 循环** | 你每轮发一次 prompt | 你说停 | 探索、小改动 |
| **Goal 循环** | 上一轮结束立即开始 | 独立验证器确认完成条件满足 | 有可检查终态的任务 |
| **Time 循环** | 时钟到点 | 你喊停或任务完成 | 轮询外部状态（部署、PR、异步任务） |
| **Proactive 循环** | 事件、webhook、心跳 | 同上 | 例行巡检、依赖告警、夜间测试分流 |

**判据**：有可检查的终态 → Goal；在等一个外部会自己变的东西 → Time；两者都不满足，就别做循环。

## 与「Loop Engineering」的关系

Loop Engineering 讲的是**能力演进**（提示 → 上下文 → Harness → 循环），本篇讲的是**循环内部怎么搭**。前者是为什么，后者是怎么做。
