# 记忆、工作区与可持续自动化

> 三件事决定 Agent 能不能「长期干活」：**记得住、有固定的地盘、有可长期运行的流程**。来源 #40、#52、#53、#38。

## 一、Agent 记忆要解决的三件事

1. **记住之前的对话内容**（即时上下文）；
2. **从用户反馈中学习**（偏好与习惯）；
3. **积累的长期信息能被稳定召回**（长期记忆）——对实际应用是「必须攻克的关键难点」。

## 按存储周期分两类

| 类型 | 范围 | 例子 |
|---|---|---|
| **短期记忆（Short-Term）** | 一次会话内 | 线程范围记忆（Thread-scoped Memory）、Session |
| **长期记忆（Long-Term）** | 跨会话持久化 | 用户偏好、项目知识、历史决策 |

在 LangGraph 中，短期记忆体现为 **Agent State（状态）**，由 **checkpointer** 持久化每个线程的状态，支持中断后恢复。

## 工程视角的三种记忆

| 类型 | 内容 | 典型实现 |
|---|---|---|
| **工作记忆** | 当前上下文窗口内的信息 | 上下文本身 |
| **情景记忆** | 历史对话 / 事件序列 | 可检索的日志、向量库 |
| **语义记忆** | 抽取并固化的知识 / 用户偏好 | 结构化档案、知识库 |

checkpointer 是「线程 ID + 状态快照」，属于短期记忆的典型实现；长期记忆则要靠显式的写入策略——**什么值得记、什么时候忘、怎么召回**，这三个问题不解决，记忆只会变成噪音。

## 二、工作区模式：给 AI 一个「地盘」

做法（#52）：

- 在**经济承受能力范围内**开一个 AI 会员；
- 在电脑或手机开一个**目录作为工作区**，把在这个工作区里要做的事都交给 AI，并让它记录成文档和资料；
- 怀疑它做不了，就问它能不能做，让它想办法。

读者反馈（#53）：非代码需求（写课件、做 PPT、整理文档）也「够用」；「很多人连工具都用不好，能开始用且用好已经很好了」。

价值：
- 上下文有边界，Agent 知道「去哪找资料」；
- 产物有落点，不会散落在对话里；
- 权限可收敛，只挂载这个目录。

## 三、可持续自动化：把想法变成长期运行的流程（#38）

Bridgic Agent 是一款**桌面应用 + 智能自动化工作流构建器**，支持 macOS / Windows。灵魂功能是斜杠指令 `/build`：只要说清楚目标，剩下的交给它。

典型需求：

- 「每天扫描项目表格里还没解决的 bug，分析原因和修复方案，生成报告后回写记录」；
- 「每周追踪 GitHub 热门项目，整理趋势并推送到飞书」。

你不需要写代码，也不需要研究一堆技能、插件、MCP 怎么配——输入 `/build` 描述需求，它会自己去探路、生成、验证，遇到需要你判断的地方再回来问你。**你负责目标和关键决策，它负责把事情往前推进。**

更重要的：做出来的不只是「一次性跑完」的任务，而是**可以长期运行、定时执行、随时修改和持续优化的工作流**。经验与流程会慢慢沉淀成「自己的生产力资产」——不是套模板，而是「你的需求、你的工作流、你的 Agent」。

## 四、一个目标描述模板

```
/build
每天 09:00 扫描 ~/project/board.csv 中 status != done 的条目：
1) 逐条分析根因，给出修复建议；
2) 生成当日 Markdown 报告写入 ~/reports/YYYY-MM-DD.md；
3) 把「需要我决策」的条目标红并单独列出；
4) 把报告摘要推送到飞书群「项目日报」。
遇到需要我判断的地方，先在报告里提问，不要自行决定。
```

拆开看，它包含：**触发器（时间）+ 数据源（路径）+ 处理规则 + 产物与落点 + 通知渠道 + 边界（不自行决定）**。这六项写全，工作流才可运行、可验收。

## 五、可持续工作流的三件套

| 要素 | 具体做法 |
|---|---|
| 持久化状态 | 记忆 / checkpoint / 数据库，记「做到哪、结论是什么」 |
| 触发器 | 定时、事件、Webhook；没有触发器就只能人肉启动 |
| 可观测与可编辑 | 人能看懂今天的产出、能改规则，否则不敢托付 |
