# Loop Engineering：从「回答一次」到「持续负责一项工作」

> 来源 #22（《Loop Engineering》，Caleb Writes Code，约 8 分钟），#49。

## 能力演进的四个阶段

| 阶段 | 名称 | 让 AI 获得的能力 |
|---|---|---|
| 1 | **提示工程（Prompt）** | 告诉 AI 做什么 |
| 2 | **上下文工程（Context）** | 让 AI 主动调用工具、获取外部信息 |
| 3 | **Harness 工程** | 帮 AI 拆解并完成超出单次上下文的长期任务 |
| 4 | **循环工程（Loop）** | 让智能体**不必等待人类反复下指令**，定期检查状态、自主发现任务、执行更新并修复问题 |

四阶段不是替代关系，而是**叠加**：没有 1 就说不上 2，没有 3 就跑不了 4。

## 它与前三个阶段的差别

| | 前三阶段 | Loop |
|---|---|---|
| 触发 | 人说一句 | 定时 / 事件 / 状态变化 |
| 结束 | 这一轮答完 | 不结束，持续负责 |
| 失败处理 | 人重新提问 | 自己发现、自己修、修不好才找人 |
| 状态 | 上下文窗口 | 持久化（checkpoint / 数据库） |

## 现状与判断

Loop Engineering 目前仍带有一定的**理论和流行词色彩**（原文亦承认），但它代表一个明确方向：**AI 从「回答一次问题」走向「持续负责一项工作」**。

这与 2025–2026 年 agentic AI 的整体转向一致——从「单轮能力」转向**长时程自主性（long-horizon autonomy）**。

## 落地的最小形态

```
每天 09:00 触发：
  1. 读取状态（昨天做到哪、有什么未决）
  2. 发现新任务（扫描 issue / 日志 / 数据）
  3. 执行（Agent 循环，产出可验收的结果）
  4. 自检（测试 / 规则）
  5. 写回状态，生成日报
  6. 需要人决策的，单独列出，不自行决定
```

第 6 条是关键：**自主不等于擅自决策。**

## 常见失败模式

1. **没有状态**：每次从零开始，等于每天重做一遍。
2. **没有止损**：循环里出错会一直循环，必须设最大轮次与失败阈值。
3. **没有可见性**：人不知道它今天做了什么，最终不敢用。
4. **目标漂移**：循环久了开始做「顺手能做的事」，而不是「该做的事」——需要固定目标文件（类似 `MAIN.md`）。

## 迁移到个人成长（#49）

同一套循环可以外挂到个人：**定义想做 → AI 帮你做成 → 你验收 → 分享出去收反馈 → 把经验写出来 → AI 帮你整素材 → 输出倒逼你系统思考**。

「小循环做项目，大循环做分享。循环建立起来、越转越快，成长就越快。」
