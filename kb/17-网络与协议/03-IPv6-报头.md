# IPv6 报头：固定 40 字节，把麻烦都挪出去

> 结论：IPv6 用**固定 40 字节、8 个字段**换处理速度——校验和、分片、选项全部移出基础头，路由器只读必要字段。

## 布局

| 字节 | 内容 |
|---|---|
| 0–3 | 版本(4 位) + 流量类别(8 位) + 流标签(20 位)，共 32 位 |
| 4–5 | 有效载荷长度(16 位) |
| 6 | 下一头部(8 位) |
| 7 | 跳数限制(8 位) |
| 8–23 | 源地址(128 位) |
| 24–39 | 目的地址(128 位) |
| 40+ | 扩展头 + 载荷 |

## 逐字段

| 字段 | 长度 | 含义 |
|---|---|---|
| 版本 | 4 位 | 6 |
| 流量类别 | 8 位 | 相当于 IPv4 的 TOS，用来标 DSCP，告诉网络这个包该怎么排队 |
| 流标签 | 20 位 | 标同一个流，标准里还没定义具体怎么用 |
| 有效载荷长度 | 16 位 | 扩展头 + 载荷的总长，不含 40 字节基础头 |
| 下一头部 | 8 位 | 紧跟基础头的扩展头类型；没有扩展头时就是 TCP/UDP 这类上层协议 |
| 跳数限制 | 8 位 | 相当于 TTL，每过一跳减一 |
| 源 / 目的地址 | 各 128 位 | — |
| 扩展头 | 可变 | 见下 |

扩展头按顺序排列：逐跳选项 → 目的选项（给第一跳） → 路由 → 分片 → 认证头 → 封装安全载荷 → 目的选项（给最终目的） → 上层协议。不是每跳都要处理所有扩展头——路由设备只看「下一头部」决定要不要继续解析。

## 和 IPv4 的五个关键差别

| 维度 | IPv4 | IPv6 |
|---|---|---|
| 字段数 | 14 个（含选项与填充） | 8 个 |
| 首部长度 | 可变（4 位长度字段，最大 60 字节） | 固定 40 字节，不用长度字段 |
| 分片 | 路由器也能分片 | **只在源和目的分片**，中间路由器不分片，靠 PMTU 机制 |
| 首部校验和 | 每跳重算 | **取消**，交给链路层与传输层校验 |
| 选项 | 放首部里，长度可变 | 改成扩展头，处理效率更高 |

首部定长带来的直接好处是：路由器不必先算「头有多长」才知道数据从哪开始，硬件转发路径更简单。

## 源文件总结的四个优点

- **效率**：取消 IP 层校验，减少重复计算；
- **规范**：分片只在端点做，中间设备不参与；
- **安全**：安全选项强制支持（如 OSPFv3 不再自带认证，全部依赖 IP 安全属性）；
- **优质**：基础头里加了流标签，保留 DSCP，便于 QoS。
