# TCP 报头：20 字节里真正管用的是序号、标志位和窗口

> 结论：TCP 头前 20 字节是固定的，剩下靠选项扩展。**序号/确认号管可靠，8 个标志位管连接状态，窗口管流控。**

## 布局

| 字节 | 内容 |
|---|---|
| 0–1 | 源端口(16 位) |
| 2–3 | 目的端口(16 位) |
| 4–7 | 序列号(32 位) |
| 8–11 | 确认号(32 位) |
| 12 | 首部长度(4 位) + 保留(4 位) |
| 13 | 标志位(8 位) |
| 14–15 | 窗口大小(16 位) |
| 16–17 | 校验和(16 位) |
| 18–19 | 紧急指针(16 位) |
| 20+ | 选项（长度须为 32 位整数倍） |

## 逐字段

| 字段 | 位宽 | 要点 |
|---|---|---|
| 源 / 目的端口 | 各 16 位 | 标识两端的应用进程 |
| 序列号 | 32 位 | 本报文第一个字节在字节流中的编号；SYN 未置位时是当前段首字节，置位时是初始序号 ISN |
| 确认号 | 32 位 | 期望收到的下一个字节编号，等于「已收到的最后一个字节 + 1」 |
| 首部长度 | 4 位 | 数据从哪开始，单位 4 字节；也就是常说的「数据偏移」 |
| 保留 | 4 位 | 必须为 0 |
| 标志位 | 8 位 | 见下表 |
| 窗口大小 | 16 位 | 从确认号开始还能收多少字节，用于流控 |
| 校验和 | 16 位 | 覆盖伪首部 + TCP 头 + 数据，收端算出来对不上就丢包 |
| 紧急指针 | 16 位 | 只有 URG=1 时才有意义，指出紧急数据的位置 |

## 八个标志位

| 位 | 含义 |
|---|---|
| CWR | 拥塞窗口减小（收到 ECE 后回告） |
| ECE | 显式拥塞通知回显，表示链路拥塞 |
| URG | 本报文含紧急数据 |
| ACK | 确认号有效 |
| PSH | 收到即上交应用层，不要缓存 |
| RST | 重置连接（严重错误或主机崩溃） |
| SYN | 建连请求 / 同意建连，只有前两次握手为 1 |
| FIN | 数据发完，可以释放连接 |

## 三个容易混的点

- **序列号**编的是字节，不是报文；所以一个大段可以拆成多个报文，每个都能算出自己的位置。
- **确认号**是「我期待收到的下一个」，不是「我收到了第几个」。
- **校验和**不只算 TCP 头：它把伪首部（源/目的 IP、协议号、TCP 长度）也算进去，所以 IP 地址参与校验。
