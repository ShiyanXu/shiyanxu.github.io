# 封装与以太网帧：数据出门时套了几层

> 结论：应用数据往外发，每过一层就套一个头——TCP 段、IP 数据报、以太网帧。**每层只管自己那一段，MTU 决定了一个帧能塞多少。**

## 封装顺序

```
用户数据
  └─ + TCP 首部            → TCP 段
       └─ + IP 首部        → IP 数据报
            └─ + 以太网首部 + 尾部 → 以太网帧
```

| 层 | 加什么 | 长度 |
|---|---|---|
| 传输层 | TCP 首部 | 20 字节起（含选项可更长） |
| 网络层 | IP 首部 | 20 字节起，最多 60 |
| 链路层 | 以太网首部 + 尾部 FCS | 14 + 4 字节 |

以太网帧的有效载荷范围是 **46–1500 字节**：小于 46 要填充，大了要在 IP 层分片。

## 以太网首部 14 字节

| 字段 | 长度 | 说明 |
|---|---|---|
| 目的 MAC | 6 字节 | 下一跳的网卡地址 |
| 源 MAC | 6 字节 | 发送方网卡地址 |
| 类型 / 长度 | 2 字节 | 上层协议是谁，见下表 |

常见 EtherType：

| 值 | 上层协议 |
|---|---|
| `0x0800` | IPv4 |
| `0x0806` | ARP |
| `0x86DD` | IPv6 |
| `0x8100` | 802.1Q（VLAN 标签） |
| `0x8847` | MPLS 单播 |
| `0x8864` | PPPoE |
| `0x8809` | LACP（链路聚合控制） |

抓包时先看这 2 个字节，就知道后面该按 IPv4、IPv6 还是 MPLS 去解析。

## MTU：分不分片取决于它

- MTU 比的是**IP 报文长度**，不含链路层的前导码与帧间隙那部分。
- 以太网默认 MTU 1500；IP 规定的最小值 68 字节，IPv6 要求链路最小 1280。
- 超过 MTU 就得在 IP 层分片（IPv6 例外，只在源和目的分片）。

一个具体例子：`ping -s 1472` 时——ICMP 头 8 字节 + IP 头 20 字节，加上 1472 正好 1500，不分片；把长度改成 1473，就会分片。
