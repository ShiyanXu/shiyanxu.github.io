# M2 模型原理

> 一句话：这一模块只回答一个问题——**一句话进去，下一个 token 是怎么被算出来的**。答案是一条链：分词 → 向量 → 注意力 → 前馈 → 采样；训练则是这条链上的参数被梯度一点点挪动。不懂这条链，调参就是玄学，看账单也看不出钱花在哪。

---

## M2-01 反向传播与梯度流

**一句话**：反向传播就是链式法则的工程化——把「最终损失对每个参数的偏导」从后往前一层层乘回去，一次前向就能拿到全部梯度。

### 是什么

前向是算值，反向是算「每个参数该往哪挪」。核心恒等式：若 `L = f(g(x))`，则 `dL/dx = dL/dg · dg/dx`。网络有多少层，就乘多少次。

两个必要构件：
- **计算图**：每次前向都记录「哪个值由哪几个值算出」，反向时照着图倒着走。
- **自动微分**：框架（PyTorch）替你建图并倒推，你只写前向。

### 怎么运作

```
loss.backward() 内部：
  1. 从 loss 出发，梯度置 1
  2. 按拓扑逆序访问每个节点
  3. 节点把自己的梯度 × 局部导数，累加给输入
  4. 遇到参数就存进 .grad
optimizer.step() 再拿 .grad 更新参数
```

关键点：**梯度是累加的**，所以每个 batch 开始必须 `zero_grad()`，否则上一步的梯度会掺进来。

手推一遍的价值（K 讲的 L5 就在做这件事）：你会看到梯度如何穿过 softmax、LayerNorm、矩阵乘；会理解为什么深网络会梯度消失——连乘的因子略小于 1，乘几十次就趋近 0。

### 什么时候用它

平时不需要手推，但三类问题必须懂：
1. 损失不降、梯度为 NaN → 要知道是连乘爆炸/除零。
2. 想改结构（自定义层） → 必须知道该层导数的量级。
3. 读论文看到「梯度裁剪」「残差」 → 才知道它们在治什么病。

### 易错点

1. **忘记清零梯度**，表现为梯度越跑越大、训练莫名发散。
2. **把「梯度大」当成「学得快」**。梯度大常常是尺度没对齐，下一步就炸。
3. **以为反向传播是独立算法**。它只是链式法则的高效实现，没有额外假设。

## M2-02 语言模型骨架

**一句话**：语言模型 = 给定前文，输出下一个 token 的概率分布；训练目标就是让正确 token 的概率变大（负对数似然），其余全部是这条主线上的换壳。

### 是什么

三代同构模型，复杂度递增但骨架相同：

| 代 | 模型 | 看多长的前文 | 关键限制 |
|---|---|---|---|
| 1 | bigram（查表） | 1 个字符 | 无法利用更早的上下文 |
| 2 | MLP | 固定窗口（如 3 个） | 窗口外全丢 |
| 3 | Transformer | 全序列（注意力） | 成本随长度平方增长 |

三件套必须同时存在：**训练**（调参数）、**采样**（生成新文本）、**评估**（算损失/困惑度）。

### 怎么运作

```
输入："cat sat on the ma"
目标：预测 "t"

1. 切 token → 查 embedding → 得到向量序列
2. 过一个网络 → 输出词表大小（如 5 万）的分数向量 logits
3. softmax → 概率分布
4. 训练：正确 token 的概率取 -log，就是损失
   采样：按概率抽一个 token，接到序列末尾，重复
```

损失 = `-log P(正确 token)`，也叫交叉熵。困惑度 `perplexity = exp(损失)`，可以粗略理解为「模型平均在几个候选之间犹豫」。

### 什么时候用它

- 想自己训一个小模型玩 → 从 bigram 起步，一天能跑通。
- 想判断某个模型「强不强」→ 看验证集困惑度与下游任务，不看参数量。
- 想解释为什么模型会编造 → 它被训练成「给最像的下一个词」，不是「给真的下一个词」。

### 易错点

1. **把训练和推理混为一谈**。训练时能看到答案算损失；推理时答案未知，只能采样。
2. **以为模型一次能输出整段**。本质是逐 token 循环，长的回复 = 多次前向。
3. **用训练损失判断模型好坏**。它只会越来越低，判据永远是**留出集**。

## M2-03 训练稳定性

**一句话**：深网络难训，是因为每层的输入分布会随前面层变动而漂移；BatchNorm 把每层输入重新拉回稳定分布，让深层网络第一次变得可训。

### 是什么

三个要盯的统计量：

| 量 | 健康区间（经验） | 异常说明 |
|---|---|---|
| 激活值均值/标准差 | 均值≈0，标准差≈1 | 逐层收缩到 0 → 信号死了 |
| 梯度范数 | 不随层数指数衰减 | 逐层趋 0 → 梯度消失 |
| 更新幅度 | 与参数尺度同量级 | 远大于 → 震荡 |

BatchNorm 做的事：对一个 batch 内同一维度的值做 `(x - 均值) / 标准差`，再乘可学的 γ 加 β。它把每层输入强行标准化。

### 怎么运作

```
对某一层输出 x（batch × 维度）：
  1. 算这个 batch 在该维度上的均值 μ、方差 σ²
  2. 标准化：x̂ = (x - μ) / sqrt(σ² + ε)
  3. 缩放平移：y = γ·x̂ + β   （γ、β 是学出来的）
```

训练用 batch 统计量，推理用训练期累计的滑动平均——这个差异是「训练正常、上线崩」的经典原因。

配套的稳定手段：残差连接（给梯度一条直通路）、梯度裁剪（防爆炸）、warmup（先小步再加速）、合适初始化（方差守恒）。

### 什么时候用它

自己训模型时必须做；只调 API 时用不上，但**要能听懂别人说「这模型训练不稳」指什么**。判断是否需要 BatchNorm 的替代（LayerNorm）：batch 很小或序列任务 → 用 LayerNorm（按单样本归一化，不依赖 batch）。

### 易错点

1. **训练/推理模式忘记切换**（`model.train()` / `model.eval()`），指标莫名其妙变差。
2. **以为归一化能治过拟合**。它主要治优化困难，正则化才是治过拟合的。
3. **只看最终损失不看中间统计**。梯度在某一层已经死了，最后只是表现为「不收敛」。

## M2-04 卷积与层级结构

**一句话**：卷积 = 用同一个小窗口在整张图上滑动，把「局部相关」和「平移不变」两个先验直接写进结构，用极少的参数换取极强的泛化。

### 是什么

两个核心思想，一句话各一条：

- **局部性**：相邻位置才可能相关，所以每个输出只看一个小窗口（如 3×3）。
- **权重共享**：同一个窗口在整张图上复用，所以参数量与图大小无关。

再加**池化/步长**做下采样：分辨率降、通道升，形成「低级边缘 → 中级纹理 → 高级物体」的层级。

### 怎么运作

```
输入 (H×W×C)
 → 卷积层：K 个 3×3 卷积核 → 输出 (H×W×K)
 → 激活（ReLU）
 → 池化/步长 2 → (H/2 × W/2 × K)
 → 重复若干次
 → 全局池化 → 全连接 → 分类
```

一维序列同样适用：WaveNet 式因果卷积沿时间轴滑，看到的是「过去 N 个 token」，这就是 CNN 也能做语言模型的原因。

### 什么时候用它

- 图像/音频/局部模式明显的序列 → CNN 仍然高效（小模型、端侧、低延迟场景优势明显）。
- 需要「位置无关的同一模式检测」（不论猫在左上还是右下都要认出来）→ 卷积天然满足。
- 长程依赖为主（整段文本的指代关系）→ 卷积不够，需要注意力。

判据：**你要的模式有多大范围？** 局部 → 卷积；全局 → 注意力；两者都要 → 混合。

### 易错点

1. **以为卷积只能做图像**。它是一维/二维/三维通用的局部特征提取器。
2. **忽略感受野**。堆 3 层 3×3 才看到 7×7，层数不够就看不清大物体。
3. **把池化当必需**。现代架构常用步长卷积或直接不做下采样，池化不是硬性组件。

## M2-05 Embedding 与向量空间

**一句话**：Embedding 是把离散符号映射成连续坐标；一旦变成坐标，「相似」就有了可计算的定义——距离和夹角。

### 是什么

- **词/文本 embedding**：把 token 或整句压成 n 维向量（常见 768、1024、1536 维）。
- **空间性质**：语义相近的落在附近；方向常有意义（经典例子：king − man + woman ≈ queen）。
- **两种用途**：模型内部的输入表示（可训练），以及独立的检索模型（专门为「相似度」训练）。

### 怎么运作

相似度用余弦：

```
cos(a, b) = (a · b) / (‖a‖ · ‖b‖)     # 取值 -1 ~ 1，越大越像
```

检索流程（RAG 的地基）：

```
离线：文档 → 切块 → 每条算一个向量 → 存进向量库（带索引）
在线：问题 → 算一个向量 → 在库里找最近的 k 条 → 交给模型
```

索引结构（HNSW、IVF）解决的是「几百万条里怎么快速找最近」，暴力算距离在规模上不可行。

### 什么时候用它

- 需要「按意思找」而不是「按字面找」→ 向量检索。
- 需要去重、聚类、打标签 → embedding + 距离。
- 需要判断两段文本是否同一主题 → embedding 比关键词稳。

判据：**查询词与文档用词不同但意思相同，还能不能找对？** 能 → 语义检索；不能 → 关键词检索（BM25）反而更好。实践中常常两者混用（混合检索）。

### 易错点

1. **以为向量维度越高越好**。维度过高在小数据上反而稀释信号，且存储成本翻倍。
2. **换 embedding 模型不重建索引**。不同模型的向量空间不可比，混用等于随机。
3. **只按长度切块**。切断句子会丢语义，块内没有完整意思时，向量也就不代表任何东西。

## M2-06 注意力机制

**一句话**：注意力让每个位置自己去「查」全局——用当前 token 当查询，和所有 token 的键比对，按相关度加权取回它们的信息。

### 是什么

三个角色，一次说清：

| 符号 | 名字 | 直觉 |
|---|---|---|
| Q | Query | 我现在想找什么 |
| K | Key | 我这条信息「关于什么」的标签 |
| V | Value | 我实际携带的内容 |

计算：`Attention(Q,K,V) = softmax(QKᵀ/√d) · V`。`QKᵀ` 算两两相关度，softmax 归一成权重，再对 V 加权求和。`√d` 是缩放，防止点积过大导致 softmax 过饱和（梯度消失）。

### 怎么运作

```
1. 每个 token 的向量分别乘三个矩阵，得到 q、k、v
2. 相关度矩阵：每个 q 与所有 k 做点积 → (序列长 × 序列长)
3. 除以 √d，过 softmax → 每行和为 1 的权重
4. 加权求和所有 v → 该位置的新表示
5. 多头：把 d 维切成 h 份，各自算完拼回来（不同头学不同的关系）
```

代价：这个 `(n × n)` 矩阵就是「注意力是平方复杂度」的来源，也是长上下文贵的根本原因。

**因果掩码**：生成式模型不能让位置 i 看到 i 之后的内容，所以在相关度矩阵上把右上角置为 −∞，softmax 后权重为 0。

### 什么时候用它

注意力解决的是「**长距离依赖**」：RNN 要把信息逐字传过来，路一长就衰减；注意力一步直达。凡是要「全局对齐」的任务（翻译、指代消解、图文对齐、检索式问答）都靠它。

判据：**两个相关信息相距多远？** 几步之内 → 卷积/RNN 够；几十上百步 → 必须注意力。

### 易错点

1. **把注意力权重当解释**。权重高不等于因果重要，这是可解释性研究反复推翻的结论。
2. **忽略复杂度**。序列翻倍，注意力计算量变四倍，长文档场景必须上稀疏/分块/线性近似。
3. **以为多头只是并行加速**。多头是为了让不同子空间学不同关系，头数太少表达力不足。

## M2-07 Transformer 与 GPT

**一句话**：Transformer = 注意力 + 前馈 + 残差 + 归一化堆成的块；GPT = 只用解码器那一半、每个位置只能看左边的 Transformer，训练目标就是预测下一个 token。

### 是什么

一个 Transformer 块（现代实现的顺序）：

```
x → LayerNorm → 多头自注意力 → 残差相加
  → LayerNorm → 前馈网络(升维→激活→降维) → 残差相加
```

四个部件各司其职：
- **注意力**：在位置之间搬运信息（混合）。
- **前馈**：对每个位置单独做非线性变换（加工）。
- **残差**：给梯度一条直通路，深网络才训得动。
- **归一化**：稳住每层输入分布。

GPT 的结构选择：**只有解码器 + 因果掩码 + 下一 token 预测**。BERT 是编码器双向，T5 是编码器-解码器。

### 怎么运作

```
token 序列 → embedding（+ 位置信息）
 → N 个 Transformer 块
 → 最后一层输出 → 映射到词表大小 → softmax
 → 取概率最高/按概率采样 → 得到下一个 token
 → 接回序列，重复
```

位置信息：早期用正弦位置编码，现在多用 RoPE（旋转位置编码），好处是能外推到更长序列。

### 什么时候用它

这就是今天所有主流大模型的骨架。理解它的实际收益：
- 看模型卡上的「层数/头数/隐藏维度/上下文长度」，知道各自影响什么。
- 判断「上下文为什么贵」= 注意力平方 + KV 缓存线性增长。
- 理解「为什么微调便宜、预训练贵」= 前者只动一小部分参数或加适配层。

### 易错点

1. **把 Transformer 等同于 GPT**。前者是架构族，后者是一个具体用法。
2. **以为参数量决定一切**。数据质量、训练 token 数、后训练方式同样决定能力。
3. **忽略位置编码的作用域**。超出训练长度的位置，模型表现会突然崩，不是平滑退化。

## M2-08 Tokenizer 与 BPE

**一句话**：分词器是模型流水线里**独立的一站**——它有自己的训练集和算法（BPE），只负责字符串与 token 之间的双向翻译，但模型的大量怪癖都出在这里。

### 是什么

- **词表**：一个固定的 token 集合（常见 3 万–20 万）。
- **两个函数**：`encode(文本) → token 列表`、`decode(token 列表) → 文本`。
- **BPE（字节对编码）**：从单字符开始，反复把「最常一起出现的相邻对」合并成新 token，合到词表满为止。

结果是一套**数据驱动的、介于字与词之间**的切分：常见词一个 token，生僻词被切成几块。

### 怎么运作

```
训练分词器：
  1. 统计语料里所有相邻字符对的出现次数
  2. 合并最高频的一对，记为新增 token
  3. 重复直到达到目标词表大小

使用：
  encode: 按学到的合并规则贪心切分 → 转成 id
  decode: id → 字节 → 文本（可逆，能拼回原文）
```

字节级 BPE（GPT 系列）先转 UTF-8 字节再合并，所以任何字符都不会「未登录」。

### 什么时候用它

三类场景必须关注分词：
1. **算成本**：计费按 token。中文一个字常占 1–2 个 token，英文一个词可能 1 个也可能 3 个。
2. **算长度**：上下文上限是 token 数，塞长文档前先估。
3. **解释怪现象**：拼写类任务（数单词里有几个 r）、算术、非英语表现差，常常是切分导致的。

### 易错点

1. **用字符数估 token 数**。中英混排、代码、emoji 偏差极大，估算误差能到 2 倍。
2. **以为分词器可以随便换**。换分词器等于换词表，模型权重全部不兼容。
3. **把「模型不会拼写」当智力问题**。很多是它压根看不到字符，只看到 token 块。

## M2-09 预训练 / SFT / RLHF

**一句话**：三个阶段各解决一个问题——预训练给它「世界的知识」，SFT 教它「按格式听话」，RLHF 让它「符合人的偏好」；三者的数据形态完全不同。

### 是什么

| 阶段 | 数据形态 | 目标 | 代价 |
|---|---|---|---|
| 预训练 | 海量原始文本，无标注 | 预测下一个 token | 极高（千卡月） |
| SFT（指令微调） | 「指令 → 理想回答」对 | 学会遵循指令、输出格式 | 中（几千到几万条） |
| RLHF / DPO | 同一问题的「好答案 / 差答案」对比 | 对齐人类偏好 | 中，但需要标注偏好 |

关键认知：预训练给的是**能力**，后训练给的是**行为**。模型「知道但不说」，或「不知道却硬编」，都是两阶段错配的表现。

### 怎么运作

```
预训练：语料 → 切 token → 预测下一个 → 反向传播（几个月，TB 级数据）
SFT：   (指令, 回答) 对 → 同样的下一 token 损失，但只在回答部分算损失
RLHF：  奖励模型学「人更喜欢哪个回答」→ 用 RL 优化主模型拿高分
DPO：  跳过奖励模型，直接用偏好对做对比损失（更简单，现在更常用）
```

### 什么时候用它

- 你要的是「知识」→ 不用自己训，检索或提示词注入更便宜。
- 你要的是「稳定输出某种格式/口吻/领域流程」→ SFT 或少量示例（few-shot）都可，先试后者。
- 你要的是「减少某类不当回答」→ 偏好对齐，但成本高，先试系统提示词与输出校验。

判据：**是模型不会，还是模型不肯按你要的方式做？** 不会 → 检索/微调；不肯 → 提示词/后处理/对齐。

### 易错点

1. **以为微调能注入新知识**。少量 SFT 主要改风格，事实性知识很难靠它灌进去。
2. **把 RLHF 当「让它更聪明」**。它优化的是偏好评分，可能同时降低事实准确率（谄媚问题）。
3. **忽视灾难性遗忘**。微调后原能力下降很常见，必须留一批通用测试集回归。

## M2-10 解码与采样

**一句话**：模型只输出概率分布，「选哪个 token」是另一套策略——temperature 改分布的陡峭度，top-k/top-p 砍掉长尾，两者共同决定「稳」还是「活」。

### 是什么

| 参数 | 作用 | 调高的效果 |
|---|---|---|
| temperature | 把 logits 除以 T 再 softmax | T↑ 分布变平 → 更随机、更有创意、更易跑偏 |
| top-k | 只保留概率最高的 k 个候选 | k↑ 更多样 |
| top-p（核采样） | 保留累计概率达 p 的最小集合 | p↑ 更多样 |
| 停止条件 | 最大 token 数 / 停止符 | 决定何时收尾 |

`temperature → 0` 近似贪心解码（每次取最高概率），输出可复现；`temperature = 1` 是模型原始分布。

### 怎么运作

```
logits (词表大小)
 → 除以 T
 → top-k / top-p 掩掉长尾（置 -∞）
 → softmax → 按概率抽一个
 → 接到序列末尾，进入下一轮
```

工程上还有两个影响体验的开关：**beam search**（保留多条候选路径，适合翻译等有唯一答案的任务）、**重复惩罚**（压制已出现的 token，缓解复读）。

### 什么时候用它

- 抽取、分类、代码、结构化输出 → T 调低（0–0.3），要稳定可复现。
- 头脑风暴、文案、命名 → T 调高（0.7–1.0），要多样性。
- Agent 调工具 → 尽量低。参数一旦随机，行为就不可复现，调试成本翻倍。

### 易错点

1. **以为 T=0 就一定确定**。并行计算与浮点误差仍可能带来微小差异。
2. **同时调 T 和 top-p**。两个都在削分布，叠加后行为难以预测，一般只调一个。
3. **用高温度做结构化输出**，然后抱怨 JSON 格式偶发损坏。

## M2-11 Scaling Laws

**一句话**：模型的损失随参数量、数据量、算力呈**幂律下降**——在双对数坐标上是一条直线，所以「加大」的收益可以提前预测，但前提是三样同步加。

### 是什么

经验规律，一句话版本：

```
损失 ≈ 常数 + a·N^(-α) + b·D^(-β)
N = 参数量，D = 训练 token 数，α、β 约 0.3 左右
```

三个直接推论：
1. **不能只加参数**。参数涨了数据不涨，模型会「喂不饱」，损失提前触底。
2. **存在计算最优配比**。给定算力预算，参数与数据有一个最省的比例（Chinchilla 结论：约每参数 20 个 token）。
3. **收益递减但可预测**。翻倍算力带来的损失下降是固定的一小截，可以据此决定「值不值得」。

### 怎么运作

工程上的用法是**小规模外推**：用几个小模型（不同 N、D）跑出损失曲线，拟合出幂律，再预测大模型的最终损失。这让「要不要花一千万训一次」变成一道可以算的题，而不是赌博。

### 什么时候用它

- 判断「某模型宣称更强」是否只是更大 → 看它是否同尺寸下更好。
- 决定微调还是换模型 → 如果你的任务在更大模型上只是略好，微调小模型通常更划算。
- 理解「为什么小模型在某些任务上够用」→ 任务难度决定了你在曲线的哪一段。

### 易错点

1. **把幂律当万能**。它描述的是**平均损失**，不描述具体能力（某能力可能突然涌现）。
2. **忽略数据质量**。同样 token 数，高质量数据的等效算力可能高好几倍。
3. **用参数量比较不同家族的模型**。分词器、数据配比、后训练方式都不同，参数不可直接比。
