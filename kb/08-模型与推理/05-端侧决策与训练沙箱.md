# 端侧决策模型（Jev）与 Agent 训练沙箱（DSeC）

> 两个看似无关、其实同源的话题：**把「判断」下沉到端侧**，和**把「电脑」做成可调度的资源**。来源 #62–#66、#65。

## 一、Jev：决策器，不是 LLM

### 定位纠偏

Jev 在外网热度爆炸，但很多 demo 的场景**不具备实际可用性**——因为它的本质是**决策器（decision maker）而不是 LLM**，决策什么完全依赖你的输入。

因此它**几乎无法替代现有 LLM**，相反是**跟 LLM 配合工作**的：根据实际生产环境的数据，用 LLM 迭代优化 Jev 的输入，从而提升单次业务的响应速度与成本效率。

### 端侧路线（#64）

有了决策模型之后，**「用端侧 LLM 做 AI 手机」的方案就过时了**：

| | 老方案（端侧 LLM） | 新方案（决策模型） |
|---|---|---|
| 硬件成本 | 用户多掏几千块 | 低 |
| 体验 | 缩小版模型，能力被阉割 | 云端大模型的扩充 |
| 能力来源 | 端侧参数 | 云端生成上百种「决策模版」下发，端侧执行决策 |
| 内存 / 功耗 | 高 | 低得多 |
| 延迟 | 较高 | 更低 |

核心理念：**把「知识」留在云端，把「判断」下沉到端侧。** 这与主流厂商的端云协同路线同源。

### 成本量级（#66）

- 比 Cerebras 的 gpt-oss-120b **便宜约 20 倍**；
- 用量面板示例：**480K tokens / $0.0181**（约 $0.042/M input，output 免费）；
- 思路：给 **System One 模型**（卡尼曼「快思考」系统）加一个特殊的工程化环境，在特定场景与 LLM 比速度、比成本。

作者判断：「这个东西以后可能会变成一种原子单位的基础运算。」也有观点认为它可以在本地用轻量方案替代，微调后在特定场景更准确。

### 落地形态（#63）

用 Codex / CC 生成一堆游戏图标 emoji 并建好本地页面，**接入 Jev 之后，用自然语言就能把你想要的东西「捞」出来**。

本质是「**意图 → 选择**」的映射：用户说「我要一个看起来像火焰的技能图标」，决策器在候选素材集里选出最匹配的项。

## 二、DSeC：给几十万 Agent 各配一台「电脑」

### 问题

DeepSeek 论文《DeepSeek Elastic Compute (DSeC): A Sandbox Infrastructure for Effective Agentic Training at Scale》（arXiv 2609.22978）：

> 大模型训练时要给几十万个 Agent 各配一台「自己的电脑」，但这些电脑绝大多数时间处于待机状态——**如何让它们既是真电脑，又不必真给每台配一整套硬件？**

### 架构要点

- `libdsec`：统一控制平面 SDK；
- 集群服务：**IAM**、**API Server**、**Placement Engine**、**Watcher**（Worker Monitor）；
- 沙箱后端：**FnCall**（预加载容器 / GPU）、**Proxy Container**（QEMU VM）、**MicroVM**（Firecracker）、**FullVM**（GPU-PV）；
- 镜像层：EROFS Images、3FS、OverlayBD Images；
- 管理面：Edge Lifecycle Management、Aether（会话管理，Create/Delete）、Chronos（Exec / File / HTTP）。

旁路式运行时通过 Proxy 通信，FnCall 走独立执行路径不经过 Proxy。

### 四种隔离级别的取舍

| 隔离级别 | 载体 | 启动速度 | 隔离强度 | 适合 |
|---|---|---|---|---|
| FnCall | 预加载容器 | 最快 | 较弱 | 短函数、工具调用 |
| MicroVM | Firecracker | 快 | 强 | 常规 Agent 任务 |
| Proxy Container | QEMU VM | 中 | 强 | 需要完整系统 |
| FullVM | GPU 直通 | 慢 | 最强 | 需要 GPU/特殊硬件 |

### 为什么沙箱成了 2026 年的关键词

行业从「预训练 Scaling」转向**「后训练 + 强化学习 + 长时程 Agent 任务」**。RL 训练需要大量与环境交互的 rollout，每个 rollout 都可能跑代码、开浏览器、装依赖、读写文件，因此对四项提出硬要求：

- **强隔离**（一次污染不能影响全局）；
- **快启动**（毫秒级）；
- **可快照 / 可恢复**（失败重试、分支探索）；
- **高利用率**（待机时能被回收调度）。

## 两个话题的共同点

| | Jev | DSeC |
|---|---|---|
| 核心问题 | 端侧算力不够 | 训练侧环境不够 |
| 解法 | 云端出模版、端侧做决策 | 统一调度 + 多级隔离 |
| 共同思想 | **把重的东西集中，把轻的东西分发** | 同左 |
